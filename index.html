Le portail cloud

Chaque client de MediReport impose son propre VPN. Plutôt que d'installer tous ces logiciels sur les postes, j'ai créé un portail qui fournit à la demande un poste Windows isolé, ouvert dans le navigateur, puis détruit après usage.

12templates de VM, un par type d'accès client
<1 minentre la demande et le poste prêt
0VM conservée après la fin de la session
100 %des sessions consignées dans les journaux
01 / 06

Une demande, un ticket

Le technicien saisit son ticket et choisit le template qui correspond au client : Windows avec FortiClient, Stormshield, GlobalProtect, Cisco, et d'autres.

02 / 06

Le bon client, automatiquement

Le portail interroge l'API de Jira, retrouve l'organisation liée au ticket et présélectionne le bon profil VPN dans la VM.

API REST Jira
03 / 06

Un clone à la demande

Proxmox clone l'un des 12 templates. Deux clonages au plus tournent en parallèle pour ne pas saturer le disque, et des VM sont préparées à l'avance pour les templates les plus demandés.

API Proxmox VEfile d'attentepool de VM
04 / 06

Démarrage et adresse IP

La VM démarre. Le portail récupère son adresse IP et crée automatiquement la connexion RDP dans Apache Guacamole.

Apache GuacamoleRDP
05 / 06

Le poste, dans un onglet

En moins d'une minute, la session s'ouvre dans le navigateur. Rien à installer sur le poste du technicien. Un collègue peut même rejoindre la session par lien pour aider.

06 / 06

Fin de session, zéro trace

Quand la session se termine, la VM est supprimée de Proxmox et la connexion de Guacamole. Qui, quel ticket, quel client, combien de temps : tout est consigné dans les journaux.

Problème 01

Le disque saturait

Plusieurs Windows qui démarrent en même temps saturaient le disque de l'hôte Proxmox.

Deux clonages simultanés au maximum, une file d'attente, et un pool de VM prêtes à l'avance.

Problème 02

Guacamole manquait de mémoire

Le serveur Guacamole recevait une requête par VM active toutes les 30 secondes.

Un seul processus interroge l'API toutes les 15 secondes et partage le résultat.

Problème 03

Des VM orphelines

Après un redémarrage du portail, certaines VM restaient allumées sans surveillance.

Au démarrage, le portail les détecte, les supprime et met les journaux à jour.

Problème 04

Des secrets en clair

Les jetons d'API apparaissaient dans la configuration.

Chiffrement avec Fernet, la clé reste sur le serveur, hors du code.

Veille technologique

Du VPN au Zero Trust

Le sujet

La sécurité des accès à distance

Faire une veille, c'est suivre l'actualité d'un domaine pour anticiper les risques et les évolutions. Le mien : comment on se connecte à distance aux réseaux d'entreprise, et comment on le sécurise.

Pourquoi

Il touche mon travail

Mon portail cloud ouvre l'accès aux réseaux des clients de MediReport à travers leurs VPN. Une faille dans ces VPN me concerne directement.

À savoir

Les failles présentées ci-dessous sont des événements réels, publiés par les éditeurs et les autorités. Ce ne sont pas mes réalisations : c'est l'actualité que je suis.

02

La réponse : le Zero Trust

L'idée : ne plus faire confiance à quelqu'un simplement parce qu'il est connecté au réseau. Chaque accès est vérifié et limité à une application précise. Le NIST a formalisé ce modèle dans sa publication SP 800-207.

VPN d'accès distant

Ce qui est ouvert
Le réseau entier, ou un large segment.
Confiance
Accordée une fois, à la connexion.
Exposition
Une passerelle visible sur Internet, cible directe.
Poste compromis
Mouvement latéral possible dans le réseau.

Zero Trust (ZTNA)

Ce qui est ouvert
Une application précise, rien d'autre.
Confiance
Réévaluée à chaque requête : identité, état du poste, contexte.
Exposition
Les applications restent invisibles tant que l'accès n'est pas accordé.
Poste compromis
Impact limité à ce que la session autorise.
03

Ce que j'en retiens

  • Les VPN sont devenus une cible prioritaire. Leurs mises à jour doivent passer en premier, y compris dans les templates du portail.
  • Les postes jetables limitent les dégâts. Une VM compromise ne survit pas à la session, et chaque client a son propre environnement.
  • Le Zero Trust est la suite logique. À terme, des accès par application pourraient remplacer certains VPN complets.

Sources : NVD (NIST) · CERT-FR cert.ssi.gouv.fr · ANSSI cyber.gouv.fr · NIST SP 800-207
